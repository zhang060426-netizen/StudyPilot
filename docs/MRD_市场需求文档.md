# StudyPilot 个人学习助手 MRD 市场需求文档

## 1. 文档定位

MRD 回答“做什么”。本文从目标市场、用户需求、竞品、机会点和功能方向角度，定义 StudyPilot 个人学习助手应该覆盖哪些市场需求。

## 2. 市场背景

AI 学习工具正在从“通用聊天问答”转向“资料驱动学习”“AI tutor”“自动生成闪卡/测验”“学习计划管理”。学生对 AI 的使用需求不只停留在获取答案，还包括：

- 管理课程资料和任务。
- 基于个人资料进行可信问答。
- 自动生成复习材料。
- 检查自己是否真的掌握知识。
- 在学术诚信边界内使用 AI。

对于课程实训学生来说，还存在一个特殊市场需求：项目不仅要可用，还要能证明自己掌握了 RAG、Agent、数据库、UI 和部署。

## 3. 目标市场

| 市场层级 | 描述 |
| --- | --- |
| 核心市场 | 人工智能应用开发技术课程实训学生 |
| 扩展市场 | 需要管理多门课程任务和笔记的大学生/高职学生 |
| 长期市场 | 需要可信资料问答、复习训练和学习计划的终身学习者 |

## 4. 用户需求

| 需求 | 用户表达 | 产品机会 |
| --- | --- | --- |
| 快速知道今天学什么 | “我今天任务太多，不知道先做哪个” | 学习驾驶舱、优先级计划 |
| 基于个人笔记问答 | “我想问我自己的课堂笔记，而不是通用答案” | RAG 问答、来源引用 |
| 自动复习 | “笔记很多，不知道怎么复习” | 闪卡、测验、错题本 |
| 降低 AI 幻觉 | “AI 说得像真的，但我不确定对不对” | 来源可信度雷达 |
| 防止过度依赖 | “我看懂答案，但自己不会做” | 引导式 Tutor、知识检查 |
| 写报告省力 | “最后报告不知道怎么写” | 实训日志、报告素材库 |
| 演示稳定 | “答辩时怕功能出问题” | 项目健康检查、Demo 数据重置 |

| 产品 | 优势 | 缺口 | StudyPilot 机会 |

## 6. 市场机会点

1. 可信学习：通用 AI 容易幻觉，学生需要“有来源”的回答。
2. 学习闭环：多数工具只做问答或闪卡，缺少任务、计划、复盘联动。
3. 反依赖：AI tutor 应帮助学生思考，而不是直接替学生完成。
4. 本地隐私：个人笔记和作业资料适合本地保存。
5. 实训适配：学生需要能直接支撑实训报告和答辩的 AI 项目。

## 7. 产品定位

StudyPilot 是面向学生的本地化 AI 学习操作系统。它把课程任务、个人笔记、RAG 问答、复习训练、错题、学习计划和实训报告连接起来，帮助学生每天知道学什么、为什么这么学、学得怎么样。

## 8. MVP 市场需求

| 模块 | 市场需求 | MVP 功能 |
| --- | --- | --- |
| 学习驾驶舱 | 用户需要快速知道今日重点 | 今日任务、课程进度、AI 推荐 |
| AI 问笔记 | 用户需要可信回答 | RAG 问答、来源引用 |
| 任务管理 | 用户需要管理 deadline | 自然语言添加/完成任务 |
| 复习训练 | 用户需要从笔记生成练习 | 闪卡、测验、错题记录 |
| 学习计划 | 用户需要安排时间 | 今日三段式学习计划 |
| 报告素材 | 实训学生需要写报告 | 日志、截图清单、核心代码说明 |

## 9. 差异化卖点

- 本地个人学习库：SQLite + Chroma 保存个人学习数据。
- 证据链 RAG：回答必须展示来源和可信度。
- Deadline + 掌握度计划：学习计划同时考虑任务紧急度和知识掌握情况。
- 反依赖 Tutor：用提示、追问、测验帮助理解。
- 实训报告助手：直接服务课程报告和答辩。

## 10. 市场成功指标

| 指标 | 目标 |
| --- | --- |
| 完成一轮核心学习闭环 | 添加任务 -> 问笔记 -> 生成计划 -> 做测验 -> 记录错题 |
| RAG 回答来源展示率 | 80% 以上问答显示来源 |
| 用户可理解度 | 用户无需看说明即可完成主要功能 |
| 报告支持度 | 能产出项目概述、截图清单、核心代码说明草稿 |
| 演示完整度 | 5 分钟内讲清项目价值和技术路径 |
