# StudyPilot ADR 架构决策记录

## ADR-001 使用 NiceGUI 作为主界面框架

状态：Accepted

背景：

实训指导书示例使用 Gradio，但 StudyPilot 的界面需要学习驾驶舱、侧边导航、任务表格、来源引用栏、复习卡片、周报和健康检查页面。Gradio 更适合模型 demo，不适合复杂产品化界面。

决策：

使用 NiceGUI 构建主界面，保留 Gradio fallback demo。

后果：

- 优点：界面更美观，布局更灵活，仍保持 Python 技术栈。
- 缺点：开发成本略高于 Gradio。

Rejected:

- Streamlit：适合数据看板，但复杂聊天、多状态交互和产品化布局不够自然。
- FastAPI + Vue/React：界面最自由，但超出 5 天实训成本。

## ADR-002 使用 SQLite 作为结构化数据库

状态：Accepted

背景：

项目需要保存待办、笔记、错题、掌握度、学习日志等结构化数据。实训环境以本地运行为主。

决策：

使用 SQLite 存储结构化数据。

后果：

- 优点：零部署、易备份、适合个人学习数据。
- 缺点：不适合多人并发和云端协作。

Rejected:

- MySQL：部署成本更高，本期没有必要。
- 纯 Excel：查询和状态更新能力不足。

## ADR-003 使用 Chroma 作为向量库

状态：Accepted

背景：

项目需要对个人笔记进行向量检索，实现 RAG 问答。

决策：

使用 Chroma 持久化保存笔记向量。

后果：

- 优点：本地运行简单，适合小规模笔记库。
- 缺点：大规模数据和复杂检索能力有限。

Rejected:

- FAISS：检索快，但 metadata 和持久化管理相对麻烦。
- 云向量库：成本和隐私压力较大。

## ADR-004 采用多智能体分工

状态：Accepted

背景：

实训要求构建智能体应用，项目包含任务管理、笔记问答、计划、复习、报告、安全等不同职责。

决策：

使用 MainAgent 负责路由，TaskAgent、NoteAgent、PlanAgent、QuizAgent、CoachAgent、ReportAgent 等分别处理具体任务。

后果：

- 优点：结构清晰，便于报告展示和代码组织。
- 缺点：比单函数调用稍复杂。

## ADR-005 RAG 回答必须展示来源与可信度

状态：Accepted

背景：

学生使用 AI 学习工具时担心幻觉和假引用。个人学习助手应避免无依据回答。

决策：

RAG 回答必须返回 sources 和 confidence。当来源不足时提示用户补充笔记或切换通用知识模式。

后果：

- 优点：提升可信度，体现 RAG 价值。
- 缺点：当笔记不足时回答会更保守。

## ADR-006 加入学术诚信护栏

状态：Accepted

背景：

学习助手不能鼓励直接代写作业或报告，需要辅助学习而不是替代学习。

决策：

加入 IntegrityAgent，对高风险请求提供提纲、思路和检查清单，不直接输出可提交完整作业。

后果：

- 优点：符合教育场景，提升项目价值观。
- 缺点：用户可能觉得限制较多。
